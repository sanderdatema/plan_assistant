  <name>Task 1: Fix stop command lock cleanup and SIGINT handler leak</name>
  <files>src/cli/commands/stop.ts, src/cli/session-reader.ts, src/cli/server-client.ts</files>
  <action>
    **B1 — stop.ts lock cleanup:**
    In the no-argument port-scan path (lines 43-66), after successfully shutting down a server
    via `/api/shutdown` or SIGTERM, call `clearLock()` with the session directory from the
    health response. Import `clearLock` from `server-client.js`.

    The health endpoint returns `{ sessionDir, pid }`. Use `sessionDir` to call `clearLock(sessionDir)`.

    **B2 — SIGINT handler leak in session-reader.ts:**
    In `awaitReviewFeedback` (line 157), the SIGINT handler is added via `process.on("SIGINT", ...)`
    but never removed. Fix:
    1. Store the handler in a named const before registering
    2. Remove it with `process.removeListener("SIGINT", handler)` in both the success path
       (inside `check` when feedback is terminal) and in the handler itself
    3. Also remove the `process.exit(0)` call — throw CliExitCode(0) instead to maintain
       the established error-handling pattern from Phase 2

    Avoid: Adding multiple cleanup points. Use a single cleanup function that closes both
    watchers and removes the SIGINT handler.
  </action>
  <verify>npm test — all existing tests pass. Manual: no MaxListenersExceededWarning in test output.</verify>
  <done>AC-1 and AC-2 satisfied</done>
</task>

<task type="auto">
  <name>Task 2: Fix promise semantics, diff subItems, and idle timer log</name>
  <files>src/cli/commands/status.ts, src/lib/utils/diff.ts, src/lib/server/idle-timer.ts, tests/diff.test.ts</files>
  <action>
    **B3 — pollFeedbackStatus promise semantics (status.ts:177):**
    Change `reject(new CliExitCode(exitCode))` to:
    ```
    resolve();
    throw new CliExitCode(exitCode);
    ```
    This won't work inside the watcher callback. Instead, restructure: resolve with the
    exitCode, then throw after the promise resolves in the caller. Specifically:
    - Change the Promise<void> to Promise<number> returning the exit code
    - In `checkFile`: call `resolve(exitCode)` instead of `reject(new CliExitCode(exitCode))`
    - In `status()` after `await pollFeedbackStatus(...)`: throw new CliExitCode(returnedCode)
    - Same for the timeout: resolve with EXIT_ERROR or keep reject(CliError) for actual errors

    **B4 — phaseToString missing subItems (diff.ts:90-102):**
    Add subItems to the `phaseToString` serialization. After the overview line, add:
    ```typescript
    ...phase.subItems.map(s => `${s.letter}. ${s.name}: ${s.content}`),
    ```
    Add a test case to tests/diff.test.ts that creates two plans with different subItems
    in a phase and verifies the diff detects the change.

    **B6 — idle timer log (idle-timer.ts:52):**
    Replace the hardcoded "5 minutes" string with a computed value:
    ```typescript
    const minutes = IDLE_TIMEOUT_MS / 60_000;
    console.log(`[idle-timer] Server idle for ${minutes} minutes, shutting down.`);
    ```

    Avoid: Changing IDLE_TIMEOUT_MS value or the timer behavior itself.
  </action>
  <verify>npm test — all tests pass including new diff subItems test</verify>
  <done>AC-3, AC-4, and AC-6 satisfied</done>
</task>

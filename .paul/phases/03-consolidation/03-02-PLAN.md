<objective>
## Goal
Consolidate the two duplicated areas identified in the code review: (1) session I/O functions duplicated between session-reader.ts and session-manager.ts, and (2) two waitForFeedback functions with the same name but different semantics.

## Purpose
Six reviewers flagged these duplications. Session I/O duplication is Shotgun Surgery — changing the storage format requires updating two files. The two waitForFeedback functions with the same name are confusing and a bug waiting to happen.

## Output
- Session-manager exports path-based read functions; session-reader imports them instead of duplicating
- waitForFeedback in session-reader renamed to `awaitReviewFeedback`
- waitForFeedback in status.ts renamed to `pollFeedbackStatus`
- Both renamed functions keep their distinct behavior (they SHOULD be different — they serve different purposes)
</objective>

  <name>Task 1: Consolidate session I/O into session-manager.ts</name>
  <files>src/lib/server/session-manager.ts, src/cli/session-reader.ts</files>
  <action>
    In src/lib/server/session-manager.ts:
    - Add a generic helper: `export function readJsonFile<T>(filePath: string): T | null`
      that does the existsSync + readFileSync + JSON.parse pattern once
    - Refactor getSession, getFeedback, getPlan to use readJsonFile internally
    - Add new path-based exports that match session-reader's signatures:
      ```
      export function readMeta(sessionDir: string): SessionMeta | null {
        return readJsonFile<SessionMeta>(join(sessionDir, "meta.json"));
      }
      export function readFeedbackByDir(sessionDir: string): FeedbackPayload | null {
        return readJsonFile<FeedbackPayload>(join(sessionDir, "feedback.json"));
      }
      export function readPlanByDir(sessionDir: string): PlanJson | null {
        return readJsonFile<PlanJson>(join(sessionDir, "plan.json"));
      }
      ```
    - Note: use `readFeedbackByDir` / `readPlanByDir` to avoid name collision with existing `getFeedback(sessionId)` / `getPlan(sessionId)`

    In src/cli/session-reader.ts:
    - Remove the local readMeta, readFeedback, readPlan functions (lines 17-45)
    - Import readMeta, readFeedbackByDir as readFeedback, readPlanByDir as readPlan from session-manager:
      `import { readMeta, readFeedbackByDir as readFeedback, readPlanByDir as readPlan } from "../lib/server/session-manager.js";`
    - Re-export them so existing consumers don't break:
      `export { readMeta, readFeedback, readPlan };`

    Avoid: Changing the server-side getSession/getFeedback/getPlan functions or their consumers.
    Avoid: Changing the SessionEntry type or findSessionDirs — those are CLI-specific and stay.
